# Resumen de sesión · 2026-05-16

Este documento deja el estado real de AFuegoLento al cierre de hoy para retomar sin reconstruir contexto.

## Objetivo de la sesión

Cerrar el backend, endurecer reservas, comentar/documentar el proyecto y rediseñar el frontend principal para acercarlo a las referencias visuales del usuario.

## Resultado corto

AFuegoLento queda como un MVP full-stack funcional con backend sólido y frontend web mucho más maduro en home, auth y reservas.

## Lo que se hizo hoy

  - forgot password

#### Menú

#### Mesas
- Se añadió el dominio `tables`.
- Se soportan tipos de mesa y mesas físicas.

#### Inventario
- Se añadió el dominio `inventory`.
- Se soportan insumos, movimientos y lectura de historial.

#### Reservas
- Se endureció la validación de negocio:
  - fecha futura
  - horario permitido
  - capacidad acorde al tipo de mesa
  - experiencia válida si aplica

  - pending
  - confirmed
  - finalized
  - cancelled
- Se corrigió el caso importante donde editar una reserva podía chocar contra su propia mesa; ahora la disponibilidad ignora la reserva actual durante la actualización.

## Decisiones importantes tomadas

1. **Backend primero, frontend encima**
   - Se priorizó dejar estable la lógica de negocio para no construir vistas sobre una base incompleta.

2. **Monorepo modular**
   - Se mantuvo la estructura por dominios porque facilita crecer auth/menu/reservations/tables/inventory sin romper todo.

3. **Auth sin navbar superior grande**
   - Para respetar el lenguaje visual del usuario, login/register/reset quedaron como pantallas transaccionales fullscreen con acceso por hamburguesa.

4. **No hardcodear secretos**
   - Se mantuvo el uso de `.env` y no se deben subir credenciales reales al repo.
